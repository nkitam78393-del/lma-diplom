# ГАЙД: LMA 2.1 — Linux Memory Analyzer (дипломная версия)
## Очень подробная пошаговая инструкция: что, где и как запускается

---

## 0. Что это и где лежит

LMA 2.1 — консольный конвейер анализа дампа памяти Linux: определение версии ядра
по сырому образу → подготовка ISF-профиля → извлечение артефактов (Volatility 3) →
перекрёстная проверка (DKOM, история bash) → энтропийная предфильтрация областей →
сигнатурное сканирование YARA → репутационная проверка хешей → хронология инцидента
→ метрики качества против эталонной разметки → отчёт (TXT/JSON/HTML).

Структура проекта:

```
lma2/
├── lma.py                     # точка входа (python3 lma.py ...)
├── lma/cli.py                 # разбор команд и конвейер analyze
├── core/
│   ├── kernel_identifier.py   # шаг 1: версия ядра по баннерам в образе
│   ├── profile_manager.py     # шаг 2: каскад ISF-профиля
│   ├── volatility_handler.py  # шаг 3: обёртка Volatility 3 / режим фикстур
│   ├── cross_view.py          # шаг 4: DKOM + эвристики bash
│   ├── malfind.py             # шаг 5: энтропия областей + классификация
│   ├── yara_scanner.py        # шаг 6: YARA (области / весь образ / гибрид)
│   ├── reputation.py          # шаг 7: хеши → локальный список / MalwareBazaar
│   ├── timeline.py            # шаг 8: хронология инцидента (НОВОЕ)
│   ├── metrics.py             # шаг 9: TP/FP/FN, F1, трудозатраты
│   ├── report_generator.py    # отчёт TXT/JSON/HTML
│   └── utils.py               # энтропия, консоль, таймеры
├── lab/make_stand.py          # генератор лабораторного стенда
├── rules/                     # 12 YARA-правил (malware, secrets, injection)
├── tests/test_lma.py          # 19 модульных тестов
├── tools/render_screens.py    # рендер скриншотов из логов
├── build_report_v2.py         # сборка docx-отчёта о проделанной работе
└── build/                     # ВСЕ результаты работы складываются сюда
```

Все команды ниже выполняются **из корня проекта** (`cd lma2`). Python нужен
версии 3.10 или новее.

## 1. Подготовка окружения (один раз)

### 1.1. Проверить Python

```bash
python3 --version        # должно быть 3.10+
```

### 1.2. Установить YARA (единственная обязательная зависимость)

```bash
pip install yara-python
```

Проверка:

```bash
python3 -c "import yara; print(yara.__version__)"
```

### 1.3. (Необязательно) Volatility 3 — только для РЕАЛЬНЫХ образов

Для лабораторного стенда Volatility 3 **не нужен** — артефакты читаются из
фикстур. Реальный режим описан в п. 9.

```bash
sudo apt install -y git python3-pip build-essential
git clone https://github.com/volatilityfoundation/volatility3 ~/volatility3
pip install -r ~/volatility3/requirements.txt
```

## 2. Шаг 1 — сгенерировать лабораторный стенд

```bash
python3 -m lab.make_stand --out build/lab --size-mib 128
```

Что происходит: создаётся синтетический образ памяти `build/lab/memory_lab.raw`
(128 МиБ) с «посаженными» артефактами:

| Артефакт | Где в образе |
|---|---|
| Баннер ядра 6.17.0-19-generic (+ ложный 5.15.0-25-generic) | 0x1000 |
| История bash (14 команд: и вредоносные, и «чистые») | 0x100000 |
| Секреты в куче (PEM-ключ, токены, shadow-хеш) + документы-двойники | 0x400000 |
| RWX-области: shellcode, упакованный ELF, текстовая (ложный кандидат) | 0x800000+ |

Рядом создаются: фикстуры вывода плагинов в формате Volatility 3
(`build/lab/plugins/`), карта атрибуции (`memory_map.json`), эталонная разметка
(`ground_truth.json`), справочник хешей (`reference_hashes.txt`).

Ожидаемый вывод:

```
[+] Стенд развёрнут: build/lab
    образ памяти      : build/lab/memory_lab.raw (128 МиБ)
    фикстуры плагинов : build/lab/plugins (pslist 9, psscan 17, bash 14, malfind 4)
    эталонная разметка: build/lab/ground_truth.json
    справочник хешей  : build/lab/reference_hashes.txt
```

## 3. Шаг 2 — полный конвейер анализа (главная команда)

```bash
python3 -m lma.cli analyze \
    -f build/lab/memory_lab.raw \
    --fixtures build/lab/plugins \
    --regions-dir build/lab/regions \
    --memory-map build/lab/memory_map.json \
    --ground-truth build/lab/ground_truth.json \
    --reputation local \
    --reference-hashes build/lab/reference_hashes.txt \
    -o build/report_full
```

Расшифровка каждого флага:

| Флаг | Значение |
|---|---|
| `-f` | анализируемый образ памяти |
| `--fixtures` | режим фикстур: артефакты берутся из стенда, Volatility 3 не запускается |
| `--regions-dir` | куда malfind выгрузил области (в стенде они уже готовы) |
| `--memory-map` | карта «офсет в образе → процесс» для атрибуции YARA-находок |
| `--ground-truth` | эталонная разметка для подсчёта метрик (шаг 9) |
| `--reputation local` | репутация по локальному справочнику (`off`/`local`/`malwarebazaar`) |
| `--reference-hashes` | путь к справочнику хешей стенда |
| `-o` | префикс файлов отчёта (будут `report_full.txt/.json/.html`) |

Конвейер печатает 9 шагов. Ключевые контрольные точки вывода:

- **Шаг 1/9** — версия ядра: `6.17.0-19-generic` (ложный баннер 5.15 отсеян по частоте);
- **Шаг 4/9** — cross-view: `скрытых процессов (уточнённый критерий): 1  4242`;
  наивный критерий курсовой давал бы 2 срабатывания (1 ложное);
- **Шаг 6/9** — YARA: `итого находок: 29  по категориям: {'malware': 22, 'secrets': 7}`;
- **Шаг 8/9** — timeline: `событий: 57`, окно наблюдения, критические события;
- **Шаг 9/9** — метрики: все детекторы F1 = 1.0,
  `контрольные «чистые» двойники: 6, ложно помечено: 0`.

Результат — три файла отчёта:

```
build/report_full.txt    — текстовый отчёт для приложения к диплому
build/report_full.json   — машиночитаемый (для SIEM/скриптов)
build/report_full.html   — веб-отчёт (открыть двойным кликом в браузере)
```

Полезные варианты запуска:

```bash
# без репутационной проверки
python3 -m lma.cli analyze -f build/lab/memory_lab.raw --fixtures build/lab/plugins \
    --regions-dir build/lab/regions --memory-map build/lab/memory_map.json \
    --ground-truth build/lab/ground_truth.json --reputation off -o build/report_fast

# отключить контекстное подавление bash (показать, что оно даёт)
python3 -m lma.cli analyze ... --no-suppress -o build/report_nosuppress

# только области, без полного образа (быстро, но теряет secrets)
python3 -m lma.cli analyze ... --yara-mode regions -o build/report_regions
```

## 4. Шаг 3 — сравнение критериев (курсовой против дипломного)

```bash
python3 -m lma.cli compare \
    --fixtures build/lab/plugins \
    --ground-truth build/lab/ground_truth.json
```

Показывает по таблицам: наивный критерий (разность множеств PID, как в курсовом)
против уточнённого (TID == PID и EXIT_STATE == TASK_RUNNING), метрики обоих, а
также работу контекстного подавления эвристик bash (какие «чистые» команды
подавлены и почему). Образ (`-f`) не нужен.

## 5. Шаг 4 — сравнение режимов YARA-сканирования

```bash
python3 -m lma.cli bench \
    -f build/lab/memory_lab.raw \
    --fixtures build/lab/plugins \
    --regions-dir build/lab/regions \
    --memory-map build/lab/memory_map.json \
    --ground-truth build/lab/ground_truth.json
```

Выводит: объём сканирования «весь образ» против «отобранные области»
(на стенде сокращение ×910), время, число находок и полноту каждого режима.
Обосновывает гибридный режим: malware/injection — по областям, secrets — по всему образу.

## 9. РЕАЛЬНЫЙ образ памяти (без фикстур) — необязательный режим

1. Получить дамп (LiME/.raw/.lime) с машины с известной версией ядра.
2. Установить Volatility 3 (п. 1.3) и dwarf2json:

```bash
wget https://github.com/volatilityfoundation/dwarf2json/releases/.../dwarf2json-linux-amd64 -O ~/dwarf2json-linux-amd64
chmod +x ~/dwarf2json-linux-amd64
```

3. Подготовить ISF-профиль (каскад: локальное хранилище → vmlinux → dwarf2json):

```bash
python3 -m lma.cli profile --kernel-version 6.8.0-45-generic
```

4. Запустить конвейер БЕЗ `--fixtures`:

```bash
python3 -m lma.cli analyze -f /путь/к/дампу.lime \
    --vol-path ~/volatility3 --dwarf2json ~/dwarf2json-linux-amd64 \
    --yara-mode hybrid --reputation malwarebazaar -o build/report_real
```

Ядро определится автоматически по баннерам в образе; ISF подберётся каскадом;
репутация пойдёт в MalwareBazaar с кешированием в `build/mb_cache.sqlite3`.

## 10. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `ModuleNotFoundError: yara` | `pip install yara-python` |
| `фикстура плагина не найдена: ...` | не запущен `lab.make_stand` (п. 2) или неверный `--fixtures` |
| `версия ядра не определена; укажите --kernel-version` | в образе нет баннера — добавить флаг `--kernel-version X.Y.Z-generic` |
| `sqlite3.ProgrammingError ... 9 ... 8` | старая версия `core/reputation.py` — обновить (исправлено в этой версии) |
| Тесты не находятся | запускать `python3 -m unittest discover -s tests` из корня проекта |
| Пустой HTML-отчёт | смотреть `build/report_full.txt`; HTML открывать в браузере, а не в редакторе |
